# Учебный блокчейн RoundRobinQuorum

Этот проект является практической частью магистерской работы которая не просто описывает устройство блокчейна в теории, а представляет собой  небольшой стенд, на котором весь процесс можно увидеть по шагам: от создания транзакции до её проверки, голосования валидаторов и появления нового блока в цепочке.

Система моделирует консорциумную сеть из четырёх валидаторов. У каждого валидатора есть собственная копия цепочки, состояние счетов, пул неподтверждённых транзакций и журнал событий. Физически все четыре узла работают внутри одного Rust-приложения. Это сознательное упрощение: проект предназначен для обучения и экспериментов, а не для использования как промышленная блокчейн-платформа.

## Что можно посмотреть в проекте

- создание и подпись транзакций с помощью Ed25519;
- вычисление идентификаторов и хешей с помощью SHA-256;
- проверку подписи, баланса и `nonce`;
- формирование блока и связь с предыдущим блоком;
- вычисление корня транзакций и `state_hash`;
- выбор автора блока по кругу;
- независимую проверку блока четырьмя логическими узлами;
- подтверждение блока при кворуме 3 из 4;
- поведение сети при отключении одного или двух валидаторов;
- обнаружение изменения ранее сохранённого блока;
- расхождение локальных копий реестра после намеренной подмены данных.


## Как это устроено

Серверная часть написана на Rust. За HTTP API отвечает `axum`, за асинхронный запуск — `tokio`, для сериализации используется `serde`. Криптографические операции выполняются библиотеками `sha2` и `ed25519-dalek`.

Интерфейс сделан на React и TypeScript и собирается через Vite. В нём можно создать транзакцию, сформировать блок, отключать валидаторов, смотреть результаты каждой проверки и запускать готовые демонстрационные сценарии.

Алгоритм согласования называется `RoundRobinQuorum`. В каждом раунде автор выбирается по формуле `round mod 4`. Активные валидаторы проверяют предложенный блок и подписывают голос. Для подтверждения нужны как минимум три корректных голоса из четырёх.

`RoundRobinQuorum` — учебный алгоритм. Он показывает круговой выбор автора, проверку блока и работу кворума, но не является реализацией PBFT, Tendermint или полноценного BFT-консенсуса.

## Быстрый запуск

Понадобятся:

- стабильная версия Rust и Cargo;
- Node.js 20 или новее;
- npm.

Сначала нужно установить зависимости и собрать интерфейс:

```bash
npm install --prefix frontend
npm run build --prefix frontend
```

Затем запустить сервер:

```bash
cargo run --release --bin round-robin-quorum-server
```

После запуска интерфейс будет доступен по адресу <http://127.0.0.1:3000>.

Если нужен другой адрес или порт, можно задать переменную `RRQ_ADDR`:

```bash
RRQ_ADDR=127.0.0.1:8080 cargo run --release --bin round-robin-quorum-server
```

## Запуск в режиме разработки

Сервер и интерфейс можно запустить отдельно. В первом терминале:

```bash
cargo run --bin round-robin-quorum-server
```

Во втором терминале:

```bash
npm run dev --prefix frontend
```

Vite откроет страницу на <http://127.0.0.1:5173> и будет передавать запросы `/api` Rust-серверу.

## Как провести обычную демонстрацию

1. Выбрать отправителя, получателя и сумму перевода.
2. Нажать «Подписать и отправить».
3. Убедиться, что транзакция появилась в пуле, а подтверждённые балансы пока не изменились.
4. Нажать «Сформировать блок».
5. Посмотреть, как каждый активный валидатор проверил блок и подписал голос.
6. Проверить число голосов и результат кворума.
7. Открыть добавленный блок в обозревателе и запустить проверку целостности цепочки.

Так хорошо видна последовательность: создание → подпись → проверка → пул → блок → голосование → кворум → фиксация.

## Готовые сценарии

В интерфейсе есть восемь воспроизводимых сценариев. Перед каждым из них сеть сбрасывается к одному и тому же начальному состоянию, поэтому предыдущие действия пользователя не влияют на результат.

| № | Сценарий | Что должно произойти |
|---:|---|---|
| 1 | Корректная транзакция | Перевод проходит все проверки, попадает в блок и изменяет балансы |
| 2 | Некорректная подпись | Изменённая после подписания транзакция отклоняется до пула |
| 3 | Недостаточный баланс | Корректно подписанный перевод отклоняется из-за нехватки средств |
| 4 | Повторная транзакция | Уже подтверждённый `id` и использованный `nonce` не принимаются повторно |
| 5 | Один валидатор отключён | Оставшиеся три валидатора образуют кворум, блок подтверждается |
| 6 | Два валидатора отключены | Двух голосов недостаточно, поэтому состояние не меняется |
| 7 | Некорректный блок | Кандидат с подменённым `previous_hash` отклоняется всеми активными узлами |
| 8 | Изменение сохранённого блока | Аудит обнаруживает изменение хеша, корня транзакций, состояния и последующей ссылки |

Восьмой сценарий намеренно изменяет только локальную копию валидатора 1. Такая операция существует исключительно в демонстрационном пространстве `/api/demo`; штатного метода редактирования подтверждённых блоков в API нет.

## Проверка проекта

Полный набор локальных проверок запускается так:

```bash
cargo fmt -- --check
cargo clippy --all-targets -- -D warnings
cargo test --all-targets
npm run check --prefix frontend
npm run build --prefix frontend
```

## Небольшой эксперимент

Отдельная программа измеряет время формирования и проверки блоков с 1, 10, 100 и 500 транзакциями при четырёх, трёх и двух активных валидаторах:

```bash
cargo run --release --bin experiment
```

Результаты нужны только для сравнения режимов этого прототипа. Они не показывают производительность реальных блокчейн-платформ, потому что здесь нет сетевого обмена между машинами, дисковой базы данных и параллельной работы независимых процессов.

## Основные маршруты API

| Метод | Маршрут | Назначение |
|---|---|---|
| `GET` | `/api/state` | Текущий снимок сети для интерфейса |
| `GET` | `/api/blocks/{height}` | Содержимое блока выбранной высоты |
| `GET` | `/api/integrity` | Проверка локальных цепочек и согласованности реплик |
| `POST` | `/api/transactions` | Создание и подписание учебной транзакции |
| `POST` | `/api/transactions/submit` | Приём готовой подписанной транзакции |
| `POST` | `/api/consensus/produce` | Формирование кандидата и запуск голосования |
| `POST` | `/api/validators/{id}/status` | Включение или отключение валидатора |
| `POST` | `/api/demo/reset` | Сброс сети к начальному состоянию |
| `POST` | `/api/demo/scenarios/{name}` | Запуск одного из восьми сценариев |

Пример перевода 25 условных единиц:

```bash
curl -X POST http://127.0.0.1:3000/api/transactions \
  -H 'Content-Type: application/json' \
  -d '{"sender":"Баир","recipient":"Бато","amount":25}'

curl -X POST http://127.0.0.1:3000/api/consensus/produce
```
